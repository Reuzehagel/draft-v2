# Draft — Domain Glossary

The ubiquitous language for Draft. Dictation is the main flow but not the only one — a **Transcription run** reaches a **Transcriber** without any of it. Use these terms exactly in code, tests, issues, and design docs — don't drift to synonyms.

## Dictation lifecycle

- **Session** — one dictation from hotkey press to pasted (or discarded) result. Owns the activation FSM(s), the live capture handle, and the monotonic **session id** used to reconcile a worker's **Outcome**. The deepened `Session` module is a pure core: its methods take an event plus `now: Instant` and return **Command**s; it performs no I/O itself. A session ends the moment its outcome is known — the terminal flash outlives it and belongs to the **Pill core**.
- **Session kind** — what a session is for: `Dictate` (transcript pasted at cursor) or `Command` (spoken instruction whose LLM answer is pasted). Set at start, read at stop to route the worker.
- **Outcome** — the terminal result of a transcription: `Delivered`, `Empty`, or `Failed`. A **Session** receives it from a worker over a channel and matches it by **session id** (a stale worker's outcome — id mismatch — is ignored); a **Transcription run** returns it as an exit code — `Delivered` and `Empty` both `0`, because silence is an honest answer and not a failure, `Failed` `1`, and over the **duration cap** `2`. That fourth code is the one thing only a **Transcription run** can report: a **Session** has no file to be too long.
- **Command** — an effect a pure core returns for the event-loop adapter to perform. `Session` returns start capture, report activity, spawn transcription; the **Pill core** returns create, set mode, show, hide, destroy. The command list is the test surface. Two of them can fail, and both are **reported back**: the adapter hands the outcome of start capture and of create to the core that asked for it, and performs whatever comes back. A fallible command is emitted on its own, since everything that would follow it is addressed to the thing it might not have produced.
- **Session activity** — what a **Session** reports it is doing, for the **Pill core** to interpret: `Recording`, `Processing{since}`, `Finished{ok}`, or `None`. Deliberately smaller than **Activity**: a session knows nothing about residency, and `Finished{ok}` is the last thing it ever says.

## Pill

- **Pill** — the overlay. It shows mic bars during capture, a breathing border while the worker runs, then a green/red flash — and, when resident, it stays on screen with nothing happening. Self-animating: it is given a logical **pill mode**, and the pill adapter derives every frame itself — the **Geom** from the **Tween** in flight, the bars from the ring buffer, the **Breath** on top.
- **Pill core** — the pure core that owns the pill's whole life, peer to the **Session** core rather than downstream of it. Holds **Presence** and **Activity**, derives the **pill mode** from them, and returns commands (create, destroy, show, hide, set mode) for the adapter. Dictation is only one of its drivers; the residency toggle, the fullscreen watcher, and the hover poller are the others. It owns the terminal flash's linger, so `Session` never schedules a pill change.
- **Create retry** — the **Pill core**'s schedule for a `Create` the adapter reported failed: 1 s later, doubling to a 30 s ceiling, from `tick` rather than from an axis change. While it is armed, **presence** cannot emit a `Create`: the residency toggle, the fullscreen watcher and the hover poll arrive as one composed value, so a watcher flipping once a second would otherwise be a create once a second. A **Session** starting retires the schedule unserved and asks immediately, because a chord press is a user asking for a pill now. It is cleared the moment nothing wants a window — a retry never outlives the state that asked for one. It never gives up, because no attempt count tells a passing failure (a display change caught mid-call) from a permanent one (exhausted GDI handles), and a pill that stopped asking would be dead until the user next touched something. Built in #54.
- **Presence** — what the pill does when no session is running: `Off` (residency toggled off), `Suppressed` (a fullscreen app has focus), or `Resident{expanded}` (on screen; `expanded` set by hover). **Composed, never pushed**: its three drivers — the residency toggle (`[pill] resident`, read at launch and on every config reload), the **fullscreen watcher** (#45), and the cursor poll (#44) — each own one fact, and the adapter turns the three into the single value the core is handed. Three writers would overwrite each other, since the cursor poll runs every loop.
- **Residency** — the pill being on screen with nothing happening, as opposed to only for the length of a **Session**. One config toggle (`[pill] resident`, default on). Off restores the session-only pill exactly, with no idle work. Built in #42.
- **Activity** — what a session is currently asking the pill to show: `None`, `Recording{origin}`, `Processing{since}`, or `Done{ok, since}`. **Activity outranks presence**, so a session is always visible — even behind a fullscreen app — and hover can never expand a pill that is recording. The state a session returns to is *derived* from presence, never remembered.
- **Origin** — how a session began: `Hotkey` or `Click` (the pill's own Dictate button). Decides presentation only, **never control** — a click-started session shows its **check** for its whole duration, but a hotkey press over one finishes it exactly as confirm would, because the keyboard is always available and a user who has forgotten how they started must still be able to stop. It reaches the `Session` core as a field on its phase and is carried through untouched: same capture, same transcription, same paste. Settled in #38; built in #47.
- **Check** — the two buttons a click-started session carries, because a mouse has no "release the key" gesture to finish with: cancel and confirm, 20px circles inside one 112×32 body laid out `7 + 20 + 12 + 34 bars + 12 + 20 + 7`. **Not the button bar** — a second list in the **Pill core**, sharing none of the bar's hover, **slab** or **label** machinery. Visible for the whole session rather than hover-gated, since a cursor drift must not hide the only way to stop it. Confirm is a filled white disc with the glyph knocked out in the body colour and cancel's is 10% white: the one piece of the pill's chrome that changes *meaning* rather than looks, giving a click-started session the obvious default action the bar deliberately lacks. **Recording only** — both leave on the 320 ms **handoff**, and Processing and Done render identically whatever started the session.
- **Cancel** — throwing a click-started session's audio away: no transcription, no paste, **no history entry and no flash**, since a flash reports an outcome and cancelling isn't one. Structural rather than flagged: nothing is spawned, so there is no **Outcome** to report. Recording-only, so a click that arrives after the **handoff** does nothing at all. The pill goes straight back to the **nub** over 110 ms — there is deliberately no reverse edge to the **button bar**. What makes that hold is the hover poll's reach, not a flag: see **click-through**.
- **Pill mode** — the logical state the **Pill core** derives from **presence** and **activity** and hands the adapter: `Hidden`, `Idle`, `Expanded{style}`, `Recording{origin}`, `Processing{since}`, `Done{ok, since}`. Transitions are commands; per-frame animation is not. `Session` does not assign it — `Session` reports **session activity**, and the pill core decides. `Hidden` means off screen, not absent: the window may still exist, and residency is what keeps it alive.
- **Button bar** — what the pill expands into on hover: `[copy] [dictate] [settings]`, as three **islands** over bare desktop or as one body, per the **body style**. Held as a *list* in the **Pill core**, and everything about it is derived from that list under either body: the bar's width, the islands or **slots**, the **slabs**, the glyph lookup and the click action. The count must be odd, which is one assertion rather than a shape baked into the drawing code. Built in #44, with each button's **label** name held in the same list since #46 and Dictate wired up in #47.
- **Island** — one button of the **button bar** under the islands **body style**, drawn as its own shape rather than as a region of one body. As tall as it is wide, capped at the bar's height — so a 32 button is a circle and the 48 Dictate a stadium, out of one expression. The flankers slide out from behind Dictate and fade in as the bar grows, their offset a pure function of the growth progress, so the fold-out stays inside the derived-frame model.
- **Body style** — which body the **button bar** wears: **islands** (three shapes, 118×32, the design) or **unified** (one body, 104×32, three uniform 32 **slots**, the same 22 **glyph box**). A toggle in the Pill pane, islands by default, and the one thing about the bar a user chooses — defensible where a picker for the button *set* was not, since the set has invariants a user can break and a body style has none. **Unified marks nothing**: one body cannot make Dictate primary by shape, and it does not do it by paint either — no resting disc, no brighter glyph, no wider slab. It is documented as the reduced option rather than a peer: it expresses strictly less, and it grows worse, because a fourth button under islands is a fourth island where under unified it re-derives one shared body's arithmetic. Kept because it is nearly free — the click-started **check** is one body under both styles, so the unified drawing path survives regardless, and the toggle costs a config key and a layout branch, not a renderer. It rides on `PillMode::Expanded` exactly as **origin** rides on `Recording`, so every frame's **Geom** still falls out of the mode alone. Settled and built in #48.
- **Slot** (unified) — one button's region of the unified body: uniform 32 for every button, Dictate's included. Not the render **slot**, which is a button's hover state riding beside the **Geom**. Measured inward from whatever edge the body has *this frame*, the way the **check**'s discs are — so on a nub-width body all three sit at the centre and part as it opens, which is the unified reading of the flankers sliding out from behind Dictate.
- **Glyph box** — the 22px box a button's icon is drawn in, the same in every **island** regardless of its width: the glyph box is not the button. A **check** button's box is the disc itself, because there is no island padding to hold the mark clear of — its own edge does that. Lucide's 24-grid maps onto 0.72 of it. Glyphs are SVG path `d` strings parsed into `tiny_skia` paths and cached per `(icon, scale)` — `UpdateLayeredWindow` at arbitrary DPI rules out both a font and a fixed-size PNG (#29).
- **Label** — the text above the **pill band**, in the pill's own window rather than a second one. It does exactly two jobs: it names the button under the cursor, which is the only thing that makes an icon-only **button bar** learnable, and it flashes "Copied" for 1000 ms when a copy lands, because Draft pastes via clipboard + Ctrl+V and a copy that worked looks identical to a click that did nothing. It reports **no status of any kind** — not the provider, not the input device, not the last error: one idea per surface, and the tray and settings are where you look things up. Nothing at all is drawn when no button is hovered. A pure state machine like the **Pill core**, returning a **fade**; the renderer measures the text, because a width needs a face and the state machine is asserted without one. Settled and built in #46.
- **Chip** — the **label**'s surface: a rounded slab in the pill's own body and hairline, sized to the text it holds. A fourth **island** above the three, and for the same reason the others have bodies — a light face over a light desktop is not text. There is exactly one, mid-crossfade included: its width lerps between the two texts while they cross inside it, rather than two chips dissolving through each other.
- **Fade** — the **label**'s whole appearance for one frame: the text it is coming from, the one it is going to, and how far along. Either side may be absent, which is the label arriving from nothing and leaving for it — one crossfade with a layer missing, not a separate appear animation. Linear over 110 ms, unlike every other **tween**: the two texts overlap in place, so their opacities have to sum to one throughout.
- **Slab** — a button's hit region: full bar height, and end to end across the bar, so nothing between two buttons is a dead zone. Under islands that is the island plus half the gap either side; under unified the **slots** already abut and each slab is exactly its own. "Full bar height" is checked rather than assumed since #46, when the **envelope** grew a **label** band the cursor can be in without being over any button. The bar's end padding is inert under either **body style** — it holds the pill expanded with nothing lit; the only difference is that bare desktop passes a click through where a body swallows it. A disabled button's slab is inert too, rather than merely unclickable.
- **Click-through** — `WS_EX_TRANSPARENT`, off **only** while the pill is showing buttons — the **button bar**, or a click-started session's **check**. During a *hotkey* session the pill shows neither, so a click passes straight through to the app being dictated into, which is where the words are going: the bare recording pill is not a stop target and is not clickable at all. Flipped by a bare read-modify-write `SetWindowLongPtrW` on the event-loop thread — never `SetWindowPos(SWP_FRAMECHANGED)`, and never `set_cursor_hittest`, which ORs the layered bit away (#20). Hover is found by *polling* the cursor against the pill's rect, since a click-through window is not a mouse target; per-button hover, once expanded, is winit's `CursorMoved`. The hover poll's stay-open reach follows the **button bar** rather than click-through, and those parted company in #47: during a click-started session the reach is the **nub**'s, which is what makes the **cancel** forward-only without anything forcing it.
- **Nub** — the pill's idle silhouette, 36×10: what **pill mode** `Idle` renders, and the shape `Hidden` keeps at zero alpha so a reveal is one motion rather than a fade plus a resize. Settled in #18; built in #42.
- **Geom** — one mode's whole appearance as interpolable numbers: size, radius, fill and border colour and alpha, border width, bar opacity, button opacity, **check** opacity. Every **pill mode** is exactly one Geom and every transition a lerp between two of them, so a frame mid-morph belongs to no mode at all — which is why the renderer takes a Geom and never a mode. If a state can't be expressed as one, the morph model is wrong. The one deliberate exception: which button the cursor is on is per-button state a whole-pill Geom cannot carry, so it rides beside it as a **slot** per button with its own 90 ms tween.
- **Slot** — how lit one button is this frame, and whether it can be lit at all. The renderer's second input beside the **Geom**, one per button. Its `hover` half comes from the **hover tween** — which button the cursor is on, plus the 90 ms crossfade to the last one, held outside `Geom` deliberately — and its `enabled` half from the **Pill core**.
- **Tween** — a transition's duration and easing, looked up per (from, to) **pill mode** pair. A zero duration is a snap, which is a real answer for some pairs rather than a missing entry. No easing overshoots.
- **Motion** — a **Tween** in flight: the **Geom** it started from, the one it is going to, and when it set off. `at(now)` is the frame. It starts from what is on screen rather than from the previous mode's Geom, so an interrupted transition continues instead of jumping.
- **Teardown** — a `Hide` or `Destroy` the pill adapter is holding until the transition taking the pill off screen has drawn its last frame. It defers *when*, never *whether*: a later `Create` or `Show` from the **Pill core** supersedes one that has not been performed.
- **Envelope** — the pill window's fixed rect, 260x80 since #46. Two bands: the **pill band** at the bottom and the **label**'s above it. A size change is pixels only: no window move, no buffer reallocation, no `UpdateLayeredWindow` resize mid-animation. One window rather than two — a second `WS_EX_NOACTIVATE` window would double the surface-hazard footprint and let the style-clobbering bug bite twice.
- **Pill band** — the bottom 36 of the **envelope**, which is what the envelope was before the **label**: the **button bar** with a margin over it for the inert end padding and the outer islands' anti-aliased edges. Every **Geom** is drawn centred in *this*, not in the surface, and it is anchored to the surface's bottom edge — so growing the envelope for the label moved the window upwards and moved the pill not at all.
- **Breath** — the sustained oscillation of the border alpha under **pill mode** `Processing`. Not a **Tween** — it has no end state, so it cannot be a lerp between two **Geom**s; it rides on top of whatever the morph produced. It never dims the border below the hairline.
- **Home monitor** — the single monitor the pill lives on: its `HMONITOR`, work-area rect (`rcWork`, never the full monitor rect), scale factor, and **autohide reserve**. There is exactly one, and `PillWindow::scale` is a property of it rather than a value captured at creation. Derived by the **monitor policy** and re-derived only while the pill is idle — latched at session start and while expanded — except on `WM_DISPLAYCHANGE`, which re-derives unconditionally and breaks the latch. The move is a hard cut, and the window is moved in place, never recreated. Settled in #22; built in #43.
- **Autohide reserve** — how much of the bottom of a monitor's `rcWork` an auto-hiding taskbar is going to cover when it slides out, in physical pixels. The one thing about a taskbar the work rect does not say: Windows reserves an auto-hiding taskbar no space, so `rcWork == rcMonitor` and the pill is placed where the taskbar will appear. Subtracted in the **home monitor**'s placement, and **zero in every pinned case** — a pinned taskbar is already out of `rcWork`, and charging it twice would push the pill up by its own height. Zero on any edge but the bottom too, deliberately: the pill is anchored bottom-centre, so a taskbar sliding out from the left, top or right is not on its way to the same pixels. Read from `SHAppBarMessage` in the Win32 half beside `enumerate()`, so it is part of the display *snapshot* and re-read exactly where that is — `WM_DISPLAYCHANGE` and a DPI change, never per poll. One query answers for the desk: Windows 11's per-monitor taskbars share the primary's setting, edge and *logical* thickness, and it is rescaled per monitor's DPI. Built in #72.
- **Monitor policy** — how the **home monitor** is derived (`[pill] monitor`): `focused` (default — the monitor holding the foreground window, because that is where the text is going to land), `cursor` (after a ~300 ms dwell, so a bezel round trip doesn't teleport the pill twice), `primary` (which doubles as the universal fallback), or `pinned`. A pin names a *monitor*, not a slot: `monitor_pinned_path` stores `QueryDisplayConfig`'s EDID-derived `monitorDevicePath`, explicitly not `\\.\DISPLAY1`. One policy governs the resident and the session-only pill alike.
- **Fullscreen watcher** — what sets **presence** `Suppressed`: a game, a video or a presentation on the pill's **home monitor**, which the pill leaves with `SW_HIDE` — never alpha 0 and never cloaking, both of which keep a composited topmost window on screen and can force the desktop compositor back into composed mode. Two signals OR'd: the foreground window's rect against its monitor's `rcMonitor` (borderless-windowed games, browser and VLC fullscreen), and `SHQueryUserNotificationState` (legacy DX exclusive, screensaver, lock, presentation mode). Driven by `EVENT_SYSTEM_FOREGROUND` *and* a 1 s poll, because nothing fires an event when an app goes fullscreen in place — or out of it, which is why a suppressed pill is a rung of the **proximity ladder** rather than a `Wait`. Guards: a maximized window is not fullscreen, shell windows are skipped, and a null foreground is *unknown* — it keeps the prior answer rather than flashing the pill back on mid-alt-tab. Settled in #19; built in #45.
- **Pill hook** — the one wndproc subclass installed on the pill's window, carrying every message winit doesn't surface. It answers `WM_MOUSEACTIVATE` itself, so a click can never move focus off the window a dictation is being pasted into, and surfaces the rest — display topology, DPI, display power, session lock, session reconnect — to the app loop as **hook events**. One hook rather than one per consumer: four subclasses would be four chances to clobber `GWLP_WNDPROC`. Settled in #21; built in #40. Since #42 its events are what re-push the layered surface, and the only thing that does, and since #49 its display-power and session-lock events are what take the **proximity ladder** to `Wait`.
- **Proximity ladder** — how long the event loop may sleep, as a function of what the pill is doing: 33 ms **animating** (a transition running, or a terminal flash waiting to be retired), 50 ms with the cursor **near** the pill, 250 ms with it **far**, 1 s while the pill is **suppressed** and only the **fullscreen watcher**'s backstop can see it come back, 1 s while the **Pill core** is holding a **create retry**, and `ControlFlow::Wait` — no timer at all — when the pill is off screen, the display is off, or the session is locked. A pure core (`pill::ladder`), and **the only thing in Draft that arms a timer**: everything else that talks to the loop wakes it instead. Near is the pill *window*'s rect grown by 180 logical px — deliberately not a hover reach, since nothing happens at its boundary but the poll speeding up. It exists because hover cannot be event-driven: a **click-through** window is not a mouse target, so the only way to find the cursor is to look. Settled in the #21 research (R10); built in #49, which folded #32.
- **Waker** — the handle every producer outside the event loop pokes it with (`wake::Waker`, an `EventLoopProxy`). The loop rests at `ControlFlow::Wait`, which wakes for a *message* and not for a channel send, so the hotkey handler, the tray menu handler, each transcription worker, the settings watcher and the update check each post one after sending. The payload is empty on purpose: the channels already carry what happened, and all the loop needs is "look again". Built in #49. **Hook events** need none — the wndproc runs on the loop's own thread, inside `DispatchMessage`.
- **Handoff** — the Recording → Processing transition. Named because it is a transition with its own treatment rather than a mode swap: the border colour crossfades while the live bars fall flat over 320 ms, so it reads as losing energy rather than stopping dead. Its clock outlives **pill mode** `Processing` — an outcome that lands inside 320 ms finds the fall still running. Settled in #18; built in #41. Since #42 the crossfade is the ordinary **Tween** between the two **Geom**s; only the bars' heights are still drained separately, because a waveform is live data rather than geometry.

## Transcription

- **Transcriber** — the seam (`trait Transcriber`) behind which every speech-to-text provider sits. `transcribe(samples) -> String`, plus `transcribe_attributed` so the provider that actually produced the text travels with the result (attribution can't race between concurrent dictations).
- **Provider** — a concrete adapter satisfying `Transcriber`: local Parakeet, Mistral, Reson8, or OpenAI/Groq via `openai_compat`. Selected by config; constructed by `transcribe::build(cfg)`, which owns key-loading, vocabulary baking, and fallback-wrapping in one place.
- **Fallback** — `FallbackTranscriber` wraps a cloud provider with the local model: on any primary error it transcribes locally instead, so a connectivity blip degrades quality rather than losing words.
- **Vocabulary hint** — a free-text decoder prompt built from the user's term list, baked into prompt-capable providers (OpenAI, Groq) at construction. Providers without biasing support ignore it; it is not part of the `Transcriber` interface.
- **Transcription run** — one execution of the `transcribe` subcommand: a media file in, text out. Not a **Session** — it has no activation, no capture, no pill, and no paste. It shares only the **Transcriber** and the **Replacements**. It is also the only flow with no history: history exists to recover a lost paste, and nothing is pasted here.
- **Decode seam** — the boundary a **Transcription run** enters through: a file path in, 16 kHz mono `f32` out, the same shape live capture produces, so everything downstream cannot tell the two apart. Owns demux, decode, channel downmix and resampling, and nothing else. Sits where the microphone sits in a **Session**.
- **Duration cap** — the longest media file a **Transcription run** accepts: ten minutes, fixed. Not per-**Provider**, not configurable, and not a property of a **Session**, which has no file. Checked twice — once against the container's own frame count so an oversized file fails before it is decoded, once against the frames actually decoded, because a header can lie or say nothing at all.

## Post-processing

- **Replacements** — the user's find/replace rules, applied to any transcript whatever produced it. They correct vocabulary, so they are true of a **Session** and a **Transcription run** alike.
- **Voice commands** — spoken instructions to Draft ("new paragraph") turned into their effect. They belong to a **Session** only: a recorded file's speaker is not addressing Draft, so applying them there corrupts text that merely contains the phrase.
