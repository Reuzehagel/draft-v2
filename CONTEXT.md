# Draft — Domain Glossary

The ubiquitous language for Draft. Dictation is the main flow but not the only one — a **Transcription run** reaches a **Transcriber** without any of it. Use these terms exactly in code, tests, issues, and design docs — don't drift to synonyms.

## Dictation lifecycle

- **Session** — one dictation from hotkey press to pasted (or discarded) result. Owns the activation FSM(s), the live capture handle, and the monotonic **session id** used to reconcile a worker's **Outcome**. The deepened `Session` module is a pure core: its methods take an event plus `now: Instant` and return **Command**s; it performs no I/O itself. A session ends the moment its outcome is known — the terminal flash outlives it and belongs to the **Pill core**.
- **Session kind** — what a session is for: `Dictate` (transcript pasted at cursor) or `Command` (spoken instruction whose LLM answer is pasted). Set at start, read at stop to route the worker.
- **Outcome** — the terminal result of a transcription: `Delivered`, `Empty`, or `Failed`. A **Session** receives it from a worker over a channel and matches it by **session id** (a stale worker's outcome — id mismatch — is ignored); a **Transcription run** returns it as an exit code — `Delivered` and `Empty` both `0`, because silence is an honest answer and not a failure, `Failed` `1`, and over the **duration cap** `2`. That fourth code is the one thing only a **Transcription run** can report: a **Session** has no file to be too long.
- **Command** — an effect a pure core returns for the event-loop adapter to perform. `Session` returns start capture, report activity, spawn transcription; the **Pill core** returns create, set mode, show, hide, destroy. The command list is the test surface.
- **Session activity** — what a **Session** reports it is doing, for the **Pill core** to interpret: `Recording`, `Processing{since}`, `Finished{ok}`, or `None`. Deliberately smaller than **Activity**: a session knows nothing about residency, and `Finished{ok}` is the last thing it ever says.

## Pill

- **Pill** — the overlay. It shows mic bars during capture, a breathing border while the worker runs, then a green/red flash — and, when resident, it stays on screen with nothing happening. Self-animating: it is given a logical **pill mode**, and the pill adapter derives every frame itself — the **Geom** from the **Tween** in flight, the bars from the ring buffer, the **Breath** on top.
- **Pill core** — the pure core that owns the pill's whole life, peer to the **Session** core rather than downstream of it. Holds **Presence** and **Activity**, derives the **pill mode** from them, and returns commands (create, destroy, show, hide, set mode) for the adapter. Dictation is only one of its drivers; the residency toggle, the fullscreen watcher, and the hover poller are the others. It owns the terminal flash's linger, so `Session` never schedules a pill change.
- **Presence** — what the pill does when no session is running: `Off` (residency toggled off), `Suppressed` (a fullscreen app has focus), or `Resident{expanded}` (on screen; `expanded` set by hover). **Composed, never pushed**: its three drivers — the residency toggle (`[pill] resident`, read at launch and on every config reload), the **fullscreen watcher** (#45), and the cursor poll (#44) — each own one fact, and the adapter turns the three into the single value the core is handed. Three writers would overwrite each other, since the cursor poll runs every loop.
- **Residency** — the pill being on screen with nothing happening, as opposed to only for the length of a **Session**. One config toggle (`[pill] resident`, default on). Off restores the session-only pill exactly, with no idle work. Built in #42.
- **Activity** — what a session is currently asking the pill to show: `None`, `Recording{origin}`, `Processing{since}`, or `Done{ok, since}`. **Activity outranks presence**, so a session is always visible — even behind a fullscreen app — and hover can never expand a pill that is recording. The state a session returns to is *derived* from presence, never remembered.
- **Origin** — how a session began: `Hotkey` or `Click` (the pill's own Dictate button). Decides presentation only, never control — a click-started session is to show buttons for its whole duration, but a hotkey release finishes it exactly as its check would. Only `Hotkey` is reachable until the Dictate button is wired up (#30) — the button renders and hovers from #44.
- **Pill mode** — the logical state the **Pill core** derives from **presence** and **activity** and hands the adapter: `Hidden`, `Idle`, `Expanded`, `Recording{origin}`, `Processing{since}`, `Done{ok, since}`. Transitions are commands; per-frame animation is not. `Session` does not assign it — `Session` reports **session activity**, and the pill core decides. `Hidden` means off screen, not absent: the window may still exist, and residency is what keeps it alive.
- **Button bar** — what the pill expands into on hover: three **islands** — `[copy] [dictate] [settings]` — with bare desktop showing between them. Held as a *list* in the **Pill core**, and everything about it is derived from that list: the bar's width, the islands, the **slabs**, the glyph lookup and the click action. The count must be odd, which is one assertion rather than a shape baked into the drawing code. Built in #44; the label naming the hovered button is #46's, and Dictate is wired up in #30.
- **Island** — one button of the **button bar**, drawn as its own shape rather than as a region of one body. As tall as it is wide, capped at the bar's height — so a 32 button is a circle and the 48 Dictate a stadium, out of one expression. The flankers slide out from behind Dictate and fade in as the bar grows, their offset a pure function of the growth progress, so the fold-out stays inside the derived-frame model.
- **Glyph box** — the 22px box a button's icon is drawn in, the same in every **island** regardless of its width: the glyph box is not the button. Lucide's 24-grid maps onto 0.72 of it. Glyphs are SVG path `d` strings parsed into `tiny_skia` paths and cached per `(icon, scale)` — `UpdateLayeredWindow` at arbitrary DPI rules out both a font and a fixed-size PNG (#29).
- **Slab** — a button's hit region: full bar height, spanning its **island** plus half the gap either side, so the desktop between two islands belongs to one of them instead of being a dead zone. The bar's end padding is inert — it holds the pill expanded with nothing lit — and a disabled button's slab is inert too, rather than merely unclickable.
- **Click-through** — `WS_EX_TRANSPARENT`, off **only** while the pill is showing buttons. During a hotkey session the pill shows none and a click passes straight through to the app being dictated into, which is where the words are going. Flipped by a bare read-modify-write `SetWindowLongPtrW` on the event-loop thread — never `SetWindowPos(SWP_FRAMECHANGED)`, and never `set_cursor_hittest`, which ORs the layered bit away (#20). Hover is found by *polling* the cursor against the pill's rect, since a click-through window is not a mouse target; per-button hover, once expanded, is winit's `CursorMoved`.
- **Nub** — the pill's idle silhouette, 36×10: what **pill mode** `Idle` renders, and the shape `Hidden` keeps at zero alpha so a reveal is one motion rather than a fade plus a resize. Settled in #18; built in #42.
- **Geom** — one mode's whole appearance as interpolable numbers: size, radius, fill and border colour and alpha, border width, bar opacity, button opacity. Every **pill mode** is exactly one Geom and every transition a lerp between two of them, so a frame mid-morph belongs to no mode at all — which is why the renderer takes a Geom and never a mode. If a state can't be expressed as one, the morph model is wrong. The one deliberate exception: which button the cursor is on is per-button state a whole-pill Geom cannot carry, so it rides beside it as a **slot** per button with its own 90 ms tween.
- **Slot** — how lit one button is this frame, and whether it can be lit at all. The renderer's second input beside the **Geom**, one per button. Its `hover` half comes from the **hover tween** — which button the cursor is on, plus the 90 ms crossfade to the last one, held outside `Geom` deliberately — and its `enabled` half from the **Pill core**.
- **Tween** — a transition's duration and easing, looked up per (from, to) **pill mode** pair. A zero duration is a snap, which is a real answer for some pairs rather than a missing entry. No easing overshoots.
- **Motion** — a **Tween** in flight: the **Geom** it started from, the one it is going to, and when it set off. `at(now)` is the frame. It starts from what is on screen rather than from the previous mode's Geom, so an interrupted transition continues instead of jumping.
- **Teardown** — a `Hide` or `Destroy` the pill adapter is holding until the transition taking the pill off screen has drawn its last frame. It defers *when*, never *whether*: a later `Create` or `Show` from the **Pill core** supersedes one that has not been performed.
- **Envelope** — the pill window's fixed rect, sized to the largest mode — the **button bar**, since #44 — with a margin over it for the inert end padding and the outer islands' anti-aliased edges. Every Geom is drawn centred inside it, so a size change is pixels only: no window move, no buffer reallocation, no `UpdateLayeredWindow` resize mid-animation.
- **Breath** — the sustained oscillation of the border alpha under **pill mode** `Processing`. Not a **Tween** — it has no end state, so it cannot be a lerp between two **Geom**s; it rides on top of whatever the morph produced. It never dims the border below the hairline.
- **Home monitor** — the single monitor the pill lives on: its `HMONITOR`, work-area rect (`rcWork`, never the full monitor rect), and scale factor. There is exactly one, and `PillWindow::scale` is a property of it rather than a value captured at creation. Derived by the **monitor policy** and re-derived only while the pill is idle — latched at session start and while expanded — except on `WM_DISPLAYCHANGE`, which re-derives unconditionally and breaks the latch. The move is a hard cut, and the window is moved in place, never recreated. Settled in #22; built in #43.
- **Monitor policy** — how the **home monitor** is derived (`[pill] monitor`): `focused` (default — the monitor holding the foreground window, because that is where the text is going to land), `cursor` (after a ~300 ms dwell, so a bezel round trip doesn't teleport the pill twice), `primary` (which doubles as the universal fallback), or `pinned`. A pin names a *monitor*, not a slot: `monitor_pinned_path` stores `QueryDisplayConfig`'s EDID-derived `monitorDevicePath`, explicitly not `\\.\DISPLAY1`. One policy governs the resident and the session-only pill alike.
- **Fullscreen watcher** — what sets **presence** `Suppressed`: a game, a video or a presentation on the pill's **home monitor**, which the pill leaves with `SW_HIDE` — never alpha 0 and never cloaking, both of which keep a composited topmost window on screen and can force the desktop compositor back into composed mode. Two signals OR'd: the foreground window's rect against its monitor's `rcMonitor` (borderless-windowed games, browser and VLC fullscreen), and `SHQueryUserNotificationState` (legacy DX exclusive, screensaver, lock, presentation mode). Driven by `EVENT_SYSTEM_FOREGROUND` *and* a 1 s poll, because nothing fires an event when an app goes fullscreen in place. Guards: a maximized window is not fullscreen, shell windows are skipped, and a null foreground is *unknown* — it keeps the prior answer rather than flashing the pill back on mid-alt-tab. Settled in #19; built in #45.
- **Pill hook** — the one wndproc subclass installed on the pill's window, carrying every message winit doesn't surface. It answers `WM_MOUSEACTIVATE` itself, so a click can never move focus off the window a dictation is being pasted into, and surfaces the rest — display topology, DPI, display power, session lock, session reconnect — to the app loop as **hook events**. One hook rather than one per consumer: four subclasses would be four chances to clobber `GWLP_WNDPROC`. Settled in #21; built in #40. Since #42 its events are what re-push the layered surface, and the only thing that does.
- **Handoff** — the Recording → Processing transition. Named because it is a transition with its own treatment rather than a mode swap: the border colour crossfades while the live bars fall flat over 320 ms, so it reads as losing energy rather than stopping dead. Its clock outlives **pill mode** `Processing` — an outcome that lands inside 320 ms finds the fall still running. Settled in #18; built in #41. Since #42 the crossfade is the ordinary **Tween** between the two **Geom**s; only the bars' heights are still drained separately, because a waveform is live data rather than geometry.

## Transcription

- **Transcriber** — the seam (`trait Transcriber`) behind which every speech-to-text provider sits. `transcribe(samples) -> String`, plus `transcribe_attributed` so the provider that actually produced the text travels with the result (attribution can't race between concurrent dictations).
- **Provider** — a concrete adapter satisfying `Transcriber`: local Parakeet, Mistral, Reson8, or OpenAI/Groq via `openai_compat`. Selected by config; constructed by `transcribe::build(cfg)`, which owns key-loading, vocabulary baking, and fallback-wrapping in one place.
- **Fallback** — `FallbackTranscriber` wraps a cloud provider with the local model: on any primary error it transcribes locally instead, so a connectivity blip degrades quality rather than losing words.
- **Vocabulary hint** — a free-text decoder prompt built from the user's term list, baked into prompt-capable providers (OpenAI, Groq) at construction. Providers without biasing support ignore it; it is not part of the `Transcriber` interface.
- **Transcription run** — one execution of the `transcribe` subcommand: a media file in, text out. Not a **Session** — it has no activation, no capture, no pill, and no paste. It shares only the **Transcriber** and the **Replacements**. It is also the only flow with no history: history exists to recover a lost paste, and nothing is pasted here.
- **Decode seam** — the boundary a **Transcription run** enters through: a file path in, 16 kHz mono `f32` out, the same shape live capture produces, so everything downstream cannot tell the two apart. Owns demux, decode, channel downmix and resampling, and nothing else. Sits where the microphone sits in a **Session**.
- **Duration cap** — the longest media file a **Transcription run** accepts: ten minutes, fixed. Not per-**Provider**, not configurable, and not a property of a **Session**, which has no file. Checked twice — once against the container's own frame count so an oversized file fails before it is decoded, once against the frames actually decoded, because a header can lie or say nothing at all.

## Post-processing

- **Replacements** — the user's find/replace rules, applied to any transcript whatever produced it. They correct vocabulary, so they are true of a **Session** and a **Transcription run** alike.
- **Voice commands** — spoken instructions to Draft ("new paragraph") turned into their effect. They belong to a **Session** only: a recorded file's speaker is not addressing Draft, so applying them there corrupts text that merely contains the phrase.
